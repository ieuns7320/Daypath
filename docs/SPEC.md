# Daypath 기획서

> 하루하루가 목표로 이어지는 길: 일정, 할 일, 로드맵을 하나로 관리하는 개인용 앱

- 작성일: 2026-11-06
- 최종 수정: 2026-11-06
- 상태: **1단계 완료**, 2단계 준비 중
- 작업 규칙: 작업이 끝날 때마다 새로 정한 내용을 이 문서에 반영한다. 결정 이력은 [11. 결정 기록](#11-결정-기록)에 쌓는다.

## 1. 개요

| 항목 | 내용 |
|---|---|
| 목적 | 본인이 직접 사용하는 일정·할 일·목표 관리 앱 |
| 사용자 | 1인 (개인용) |
| 지원 기기 | 아이패드, Windows PC, 맥북, 휴대폰 |
| 형태 | 반응형 웹앱 (PWA), 홈 화면 설치 지원 |

| 차별점 | 로드맵(목표 → 마일스톤 → 일정/할 일) 연결과 진행률 자동 계산 |

## 2. 기술 스택

| 영역 | 선택 (버전) | 이유 |
|---|---|---|
| 프론트엔드 | Next.js 16 (App Router, Turbopack) · React 19 · TypeScript | 생태계가 크고 PWA 구성이 쉬움 |
| 스타일 | Tailwind CSS 4 | 디자인 토큰을 CSS 변수로 관리 |
| 캘린더 UI | FullCalendar **7** (`@fullcalendar/react` 하나에 플러그인 포함) | 일간/주간/월간, 드래그·리사이즈, 터치 기본 지원 |
| 다크 모드 | next-themes | 시스템/라이트/다크 전환 |
| 백엔드 / DB | Supabase (Postgres, Auth, Realtime) | 로그인, DB, 실시간 동기화, 예약 작업(알림) |
| 배포 | Vercel (예정) | 무료, Git 연동 자동 배포 |
| 알림 | Web Push (예정) | PWA 푸시 알림 |

비용: 개인 사용 규모에서는 무료 티어로 운영 가능.

### 저장 모드

| 모드 | 조건 | 동작 |
|---|---|---|
| 클라우드 | `.env.local`에 Supabase URL·Publishable key가 있음 | 로그인 필요, 기기 간 실시간 동기화 |
| 로컬 | 환경 변수가 없음 | 로그인 없이 브라우저(localStorage)에만 저장 (개발·체험용) |

- Supabase 프로젝트: 리전 서울, 이메일+비밀번호 로그인
- `.env.local`은 git에 올리지 않는다. 다른 PC에서는 `.env.example`을 복사해 새로 만든다.

### 구현 시 주의 (라이브러리 버전 차이)

- **FullCalendar 7**은 v6와 옵션 이름이 일부 다르다. 예: `slotLabelFormat` → `slotHeaderFormat`, `eventClassNames` → `eventClass`. 내부 CSS 클래스명이 난독화되어 있어 `.fc-timegrid-event` 같은 선택자를 쓸 수 없다. 색은 `--fc-classic-*` 변수로 바꾼다.
- `useCalendarController`는 첫 렌더 중 상태를 바꿔 React 에러가 나므로 쓰지 않는다. 대신 `ref.getApi()`와 `datesSet` 콜백을 쓴다.
- **Next.js 16**은 Cache Components가 켜져 있어서, 현재 시각을 쓰는 캘린더는 `dynamic(..., { ssr: false })`로 브라우저에서만 렌더링한다.

## 3. 핵심 개념

### 일정 (Event)과 할 일 (Task)는 별개

| | 일정 | 할 일 |
|---|---|---|
| 본질 | 특정 시간에 일어나는 일 | 해야 하는 일 |
| 시간 | 시작/종료 일시 (필수) | 마감일 (선택) |
| 종일 / 여러 날 | 지원 | 해당 없음 |
| 반복 | 지원 | **지원 안 함** |
| 완료 체크 | 없음 | 있음 |
| 시간 배치 | 기본 속성 | 타임 블로킹으로 "작업 시간" 배정 가능 |
| 캘린더 모양 | 카테고리 색으로 칠한 블록 | 체크박스 (배치 시 점선 테두리 블록) |

### 카테고리와 태그

| | 카테고리 | 태그 |
|---|---|---|
| 개수 | 항목당 **1개** | 항목당 **여러 개** |
| 색상 | 있음 (캘린더 블록 색) | 있음 (블록 안 작은 칩/점) |
| 필터 | 지원 | 지원 |

- 색상은 라이트/다크 모드 양쪽에서 잘 보이도록 조정한 **프리셋 팔레트 10색**에서 선택: 회색 `gray`, 빨강 `red`, 주황 `orange`, 노랑 `amber`, 초록 `green`, 청록 `teal`, 파랑 `blue`, 남색 `indigo`, 보라 `purple`, 분홍 `pink`.
  - DB에는 색 이름(키)만 저장하고, 실제 색 값은 CSS 변수 `--c-<키>`가 모드별로 정한다.
- 카테고리가 없는 일정은 회색 블록으로 표시한다.
- 카테고리를 지우면 그 카테고리의 일정은 "카테고리 없음"이 된다. 태그를 지우면 일정에 붙어 있던 그 태그도 함께 떼어진다.

### 로드맵 (B 형식: 계층형)

```
목표 (Goal)
 └ 마일스톤 (Milestone)
     ├ 할 일 (Task)   → 진행률 계산에 포함
     └ 일정 (Event)   → "관련 일정"으로만 표시, 진행률 제외
```

- 마일스톤 진행률 = 연결된 할 일 중 완료된 비율
- 목표 진행률 = 하위 마일스톤 진행률 종합

## 4. 데이터 구조 (개념)

| 엔티티 | 주요 속성 |
|---|---|
| **Event** | 제목, 시작 일시, 종료 일시, 종일 여부, 카테고리, 태그[], 반복 규칙, 알림[], 메모, 마일스톤(선택) |
| **Task** | 제목, 마감일(선택), 작업 시간 시작/종료(선택, 타임 블로킹), 완료 여부, 완료 일시, 카테고리, 태그[], 알림[], 메모, 마일스톤(선택) |
| **Category** | 이름, 색상, 정렬 순서 |
| **Tag** | 이름, 색상 |
| **Goal** | 제목, 설명, 시작일, 목표일 |
| **Milestone** | 제목, 소속 목표, 목표일, 정렬 순서 |
| **RecurrenceRule** | 반복 단위(일/주/월/년), 간격, 요일, 종료 조건, 예외 날짜 |
| **Reminder** | 대상(일정/할 일), 알림 시점(상대 시간) |
| **PushSubscription** | 기기별 웹 푸시 구독 정보 |

반복 일정 수정 시 선택지: **이 일정만 / 이후 모든 일정 / 전체 일정**

### 현재 DB 테이블 (1단계, `supabase/schema.sql`)

| 테이블 | 컬럼 |
|---|---|
| `categories` | id, user_id, name, color, sort_order, created_at |
| `tags` | id, user_id, name, color, created_at |
| `events` | id, user_id, title, start_at, end_at, all_day, category_id → categories (삭제 시 null), tag_ids `uuid[]`, memo, created_at, updated_at |

- 시간은 `timestamptz`로 저장하고, 화면에서는 기기의 로컬 시간대로 보여준다.
- `end_at`은 **끝 미포함** 규칙이다. 종일 일정은 마지막 날 다음 날 자정이 `end_at`이다. 편집 창에서는 하루를 빼서 "마지막 날"로 보여준다.
- 태그는 개인용이라 별도 연결 테이블 없이 `events.tag_ids` 배열로 저장한다.
- 보안: 모든 테이블에 RLS(본인 `user_id` 행만 접근). 로그인한 사용자(`authenticated`)에게만 테이블 권한을 주고 `anon`은 막는다. `user_id`는 기본값 `auth.uid()`로 자동 기록된다.
- 실시간: 세 테이블 모두 `supabase_realtime`에 등록되어 있다. 변경이 오면 300ms 모아서 전체를 다시 불러온다.
- 저장은 낙관적 업데이트(화면 먼저 반영 → 저장)로 하고, 실패하면 상단 배너로 알린 뒤 서버 상태로 되돌린다.

## 5. 화면 구성

### 5.1 전체 레이아웃

- **데스크톱 / 아이패드 가로**: 왼쪽 사이드바 (캘린더 · 할 일 · 로드맵 · 카테고리 목록 · 태그 목록 · 설정) + 메인 영역
  - 사이드바의 카테고리/태그 클릭 시 필터로 동작 (2단계. 1단계에서는 목록 표시만)
  - 로컬 모드일 때 사이드바 아래에 "로컬 모드" 안내 표시
- **모바일** (폭 768px 미만): 상단 헤더 (기간 이동, 일/주/월 전환) + 하단 탭바 (캘린더 · 할 일 · 로드맵 · 설정)
- 공통: 우측 하단 `+` 빠른 추가 버튼 → 보고 있는 날짜의 **다음 정각부터 1시간** 초안

### 5.2 캘린더 탭

- 보기 전환: **일간 / 주간 / 월간** (기본: 주간). 보기를 바꿔도 보던 날짜를 유지한다.
- 한 주의 시작: **일요일**
- 모바일 주간 보기는 **3일 보기**를 기본으로 함 (버튼 이름도 "3일")
- 시간 표기: **24시간제** (시간축 `08:00`, 일정 `14:30~15:30`)
- 시간축: 30분 칸, 드래그는 15분 단위로 맞춤, 처음 열면 08:00 위치로 스크롤
- 현재 시각 빨간 선 표시
- 일정 블록 내용: 시간 · 제목 · 태그 색 점 (좁으면 제목이 다음 줄로)

**일간 / 주간 (시간축 타임라인)**
```
        일        월        화
      ┌────────┬────────┬────────┐
종일   │■ 출장 ──────────────▶   │   ← 종일·여러 날 일정
할 일  │☐ 보고서 │☑ 장보기 │☐ 과제   │   ← 마감일 있는 할 일
      ├────────┼────────┼────────┤
09:00 │■ 회의   │        │        │   ← 시간 일정 (카테고리 색 블록)
10:00 │        │┊☐ 보고서┊│        │   ← 작업 시간을 배정한 할 일 (점선)
      └────────┴────────┴────────┘
```

**월간**
- 일정: 카테고리 색 막대, 칸이 넘치면 "+N개 더"
- 할 일: 날짜 칸에 `☐ 3`처럼 개수만 요약, 클릭 시 펼침

**드래그 (1단계부터 필수, 마우스와 터치 모두 지원)**
- 일정 블록 드래그 → 시간/날짜 이동 (종일 칸 ↔ 시간 칸 이동도 가능)
- 일정 블록 끝 드래그 → 기간 조절
- 빈 시간대 드래그 → 해당 범위로 새 일정 추가 창 열기
- 빈 시간대 **한 번 클릭** → 그 시각부터 **1시간짜리** 새 일정
- 일정 클릭 → 수정 창
- 터치: 0.25초 길게 누른 뒤 끌기
- 편집 창이 열려 있는 동안에는 캘린더 드래그·선택을 꺼서 클릭이 캘린더로 새지 않게 한다.
- 할 일 드래그 → 타임라인에 작업 시간 배정 (2단계)

**표시 옵션**
- "할 일 표시" ON/OFF 토글
- 완료한 할 일은 흐리게 표시하고 취소선 처리

### 5.3 일정 / 할 일 추가·수정 창

```
┌─────────────────────────────────┐
│  [ 일정 | 할 일 ]          ✕    │
├─────────────────────────────────┤
│  제목                            │
│  🕐 날짜·시간   ☐ 종일  ↻ 반복    │
│  ■  카테고리                      │
│  #  태그 (여러 개)                │
│  🔔 알림 (여러 개)                │
│  ◎  로드맵 연결 (마일스톤)         │
│  ≡  메모                         │
├─────────────────────────────────┤
│                [삭제]  [ 저장 ]  │
└─────────────────────────────────┘
```
- 할 일 모드: 시간 대신 "마감일(선택)", 반복 항목 숨김, 완료 체크 표시
- 데스크톱은 가운데 팝업, 모바일은 하단 시트
- 1단계 구현 범위: 제목, 시작/종료(날짜·시간), 종일, 카테고리(칩 1개 선택, 기본값은 첫 카테고리), 태그(칩 여러 개), 메모, 삭제
  - 반복·알림·로드맵 연결은 해당 단계에서 추가
  - 시작을 바꾸면 길이를 유지한 채 종료도 함께 이동한다.
  - 종료가 시작보다 앞서면 저장 시 1시간짜리로 보정한다.
  - 제목이 비면 "(제목 없음)"으로 저장한다.
  - Esc 또는 바깥 클릭으로 닫는다.
  - 시간 입력칸은 브라우저 기본 컨트롤이라 OS 언어 설정을 따른다(오전/오후로 보일 수 있음).

### 5.4 할 일 탭

- 그룹: **지난 마감 / 오늘 / 이번 주 / 이후 / 마감일 없음 / 완료됨(접힘)**
- 정렬: 마감일순, 생성순
- 필터: 카테고리, 태그
- 데스크톱: 할 일 목록과 주간 캘린더를 나란히 띄워 **타임 블로킹 모드** 지원

### 5.5 로드맵 탭

- **트리 보기**: 목표 → 마일스톤 → 할 일/일정 계층, 각 단계 진행률 막대
- **타임라인 보기**: 목표와 마일스톤을 시간축 가로 막대로 표시
- 목표/마일스톤 추가·수정·삭제

### 5.6 설정

- 테마: 시스템 / 라이트 / 다크
- 카테고리 관리 (이름, 색상, 순서)
- 태그 관리 (이름, 색상)
- 알림 권한 및 기본 알림 시점 (3단계)
- 계정 (로그아웃)
- 카테고리·태그는 목록에서 이름을 바로 고치고(Enter/포커스 해제 시 저장), 왼쪽 표시를 눌러 색을 바꾸며, 삭제 전에 확인을 받는다.

### 5.7 로그인

- 클라우드 모드에서만 표시. 이메일 + 비밀번호 로그인 / 계정 만들기 전환
- Supabase 기본 설정상 가입 후 확인 메일의 링크를 눌러야 로그인할 수 있다.

## 8. 개발 단계 (MVP 로드맵)

## 10. 다른 PC에서 이어서 작업하기

1. Git과 Node.js(20.9 이상, 현재 v24 사용)를 설치한다.
2. `git clone https://github.com/ieuns7320/Daypath.git` 후 `npm install`
3. `.env.example`을 복사해 `.env.local`을 만들고 Supabase URL·Publishable key를 넣는다. 값은 Supabase 대시보드 Project Settings → API에서 확인한다.
4. `npm run dev` 후 같은 계정으로 로그인한다.
5. 작업을 시작할 때는 `git pull`, 끝낼 때는 커밋 후 `git push`를 한다.
