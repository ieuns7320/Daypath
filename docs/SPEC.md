### 구현 시 주의 (라이브러리 버전 차이)

- **FullCalendar 7**은 v6와 옵션 이름이 일부 다르다. 예: `slotLabelFormat` → `slotHeaderFormat`, `eventClassNames` → `eventClass`. 내부 CSS 클래스명이 난독화되어 있어 `.fc-timegrid-event` 같은 선택자를 쓸 수 없다. 색은 `--fc-classic-*` 변수로 바꾼다.
- `useCalendarController`는 첫 렌더 중 상태를 바꿔 React 에러가 나므로 쓰지 않는다. 대신 `ref.getApi()`와 `datesSet` 콜백을 쓴다.
- `<FullCalendar>` 자체도 화면에 붙기 전에 내부 상태를 바꿀 수 있어서, 페이지 전환(트랜지션) 렌더 중에 만들어지면 같은 에러("Can't perform a React state update on a component that hasn't mounted yet")가 난다. 그래서 캘린더 화면이 마운트된 뒤(`mounted` 상태)에만 그린다.
- FullCalendar 7의 외부 드래그는 `@fullcalendar/react/interaction`의 `Draggable` + `droppable` 옵션 + `drop` 콜백으로 한다. `eventData.create: false`로 두면 캘린더에 항목을 직접 만들지 않고 콜백에서 데이터만 바꾼다. `updateSize()`는 v7에 없다.
- **Next.js 16**은 Cache Components가 켜져 있어서, 현재 시각이나 localStorage를 쓰는 화면(캘린더, 할 일 탭)은 `dynamic(..., { ssr: false })`로 브라우저에서만 렌더링한다.
- 로컬 모드 확인용 서버: `.claude/launch.json`의 `daypath-local-mode`(포트 3001)는 Supabase 환경 변수를 비운 채 `next dev`를 띄운다. 클라우드 데이터를 건드리지 않고 시험할 때 쓴다.

## 3. 핵심 개념

### 일정 (Event)과 할 일 (Task)는 별개 (서로 영향을 주지 않는다)

| | 일정 | 할 일 |
|---|---|---|
| 본질 | 특정 시간에 일어나는 일 | 해야 하는 일 |
| 시간 | 시작/종료 일시 (필수) | **하는 날** (날짜만, 없을 수도 있음) |
| 종일 / 여러 날 | 지원 | 해당 없음 |
| 반복 | 지원 | **지원 안 함** |
| 완료 체크 | 없음 | 있음 |
| 보이는 곳 | 캘린더 탭만 | 할 일 탭만 (캘린더에는 나오지 않음) |
| 모양 | 카테고리 색 **실선 테두리** 블록 (칠하지 않음) | 카테고리 색 체크박스 + 제목 |

### 카테고리와 태그

| | 카테고리 | 태그 |
|---|---|---|
| 개수 | 항목당 **1개** | 항목당 **여러 개** |
| 색상 | 있음 (캘린더 블록 테두리 색) | 있음 (캘린더에서는 이름 앞 점 색) |
| 필터 | 지원 | 지원 |

- 색상은 라이트/다크 모드 양쪽에서 잘 보이도록 조정한 **프리셋 팔레트 10색**에서 선택: 회색 `gray`, 빨강 `red`, 주황 `orange`, 노랑 `amber`, 초록 `green`, 청록 `teal`, 파랑 `blue`, 남색 `indigo`, 보라 `purple`, 분홍 `pink`.
  - DB에는 색 이름(키)만 저장하고, 실제 색 값은 CSS 변수 `--c-<키>`가 모드별로 정한다.
- 카테고리가 없는 일정은 회색 테두리로 표시한다.
- 캘린더에서는 색을 **칠하지 않고 테두리로만** 구분한다. 블록 안은 바탕색, 글자는 기본 글자색이다.
- **캘린더용과 할 일용 카테고리·태그는 따로**다(2026-11-09, `kind` = `event` / `task`). 일정에는 캘린더용만, 할 일에는 할 일용만 붙는다. 사이드바와 모바일 필터는 보고 있는 탭 것만 보여 준다(할 일 탭이면 할 일용, 그 밖에는 캘린더용). 설정에서는 [캘린더 | 할 일] 전환으로 따로 관리한다.
- 편집 창은 다른 쪽 카테고리·태그가 남아 있는 항목을 열면 그 연결을 떼고 시작한다(저장하면 정리됨).
- 카테고리를 지우면 그 카테고리의 일정·할 일은 "카테고리 없음"이 된다. 태그를 지우면 일정·할 일에 붙어 있던 그 태그도 함께 떼어진다.
- 필터 규칙: 같은 묶음 안에서는 **OR**(업무 또는 개인), 카테고리와 태그 사이는 **AND**(업무이면서 #중요). 필터는 탭마다 따로(캘린더 필터 / 할 일 필터) 기억하고, 새로고침하면 풀린다(저장하지 않음). 지워진 카테고리·태그는 필터에서 자동으로 빠진다.

### 로드맵 (B 형식: 계층형)

```
목표 (Goal)
 └ 마일스톤 (Milestone)
     ├ 할 일 (Task)   → 진행률 계산에 포함
     └ 일정 (Event)   → "관련 일정"으로만 표시, 진행률 제외
```

- 마일스톤 진행률 = 연결된 할 일 중 완료된 비율. **연결된 할 일이 없으면 직접 체크**(완료 0% / 100%)
- 목표 진행률 = 마일스톤 진행률의 **평균** (마일스톤이 없으면 0%). 마일스톤 하나는 진행률 100%일 때 "완료"로 센다
- 일정은 진행률에 넣지 않고 마일스톤 아래 "관련 일정"으로만 보여 준다
- 할 일·일정은 마일스톤 하나에만 연결된다(`milestone_id`, 선택). 목표에 바로 연결하지 않는다
- 목표는 지우지 않고 **보관**할 수 있다(보관함에서 다시 꺼냄). 목표를 지우면 마일스톤도 지워지고, 연결된 할 일·일정은 남되 연결만 풀린다

- 스키마 변경은 `supabase/migrations/`에 번호를 붙인 SQL 파일로 추가하고, Supabase SQL Editor에서 순서대로 실행한다. `schema.sql`은 1단계 기본 테이블이다.
- `tasks`: `due_date` 칸은 이름과 달리 **그 일을 하는 날**이다(2026-11-09부터, 칸 이름은 바꾸지 않음). 시간대 영향을 받지 않도록 날짜 타입이다. `scheduled_start`·`scheduled_end`(작업 시간)는 화면에서 더 쓰지 않지만 기존 데이터를 지우지 않으려고 칸과 값은 그대로 둔다(편집 창 저장 시에도 원래 값 유지). 두 칸은 둘 다 있거나 둘 다 비어 있어야 한다(DB 제약).
- 앱이 `tasks` 테이블을 못 찾으면(마이그레이션 미실행) 나머지 데이터는 그대로 보여 주고, 상단 배너로 "002_tasks.sql을 실행해 달라"고 안내한다.
- `categories.kind` 칸이 없으면(004 미실행) 모두 캘린더용으로 보고, 저장할 때 kind를 빼고 보낸다. 003·004가 둘 다 없으면 배너 하나에 함께 안내한다.
- 004는 기존 카테고리·태그를 모두 캘린더용으로 두고, **기존 할 일의 카테고리·태그 연결을 뗀다**(사용자 결정: 할 일용은 새로 만든다). 할 일 자체는 지우지 않는다.
- `goals`·`milestones`가 없으면(006 미실행) 배너로 "006_roadmap.sql을 실행해 달라"고 안내하고, 로드맵은 비어 있으며, 할 일·일정을 저장할 때 `milestone_id`를 빼고 보낸다. 실시간 구독도 두 테이블은 별도 채널(`daypath-sync-roadmap`)이라 없어도 다른 동기화가 깨지지 않는다.
- `goals.start_date`가 없으면(007 미실행) 배너로 안내하고, 목표를 저장할 때 `start_date`를 빼고 보낸다(타임라인은 만든 날부터 그림).
- `events.rrule` 칸이 없으면(003 미실행) 마찬가지로 배너로 "003_recurrence.sql을 실행해 달라"고 안내하고, 저장할 때 반복 칸을 빼고 보낸다(반복이 아닌 일정은 계속 쓸 수 있다).

### 반복 일정 저장 규칙 (3a)

- 반복 일정은 **한 행**(시리즈)에 첫 회차의 시작·종료와 `rrule`을 저장하고, 화면에 보이는 기간만 앱에서 회차로 펼친다(`lib/recurrence.ts`). 회차를 미리 만들어 두지 않는다. FullCalendar rrule 플러그인은 쓰지 않는다.
- `rrule`은 RFC 5545 RRULE의 일부만 쓴다: `FREQ`(DAILY/WEEKLY/MONTHLY/YEARLY), `INTERVAL`, `BYDAY`(매주일 때만, 여러 요일), `UNTIL=YYYYMMDD`(**그날 포함**, 날짜만), `COUNT`. 예: `FREQ=WEEKLY;INTERVAL=2;BYDAY=MO,WE;COUNT=5`
- 회차의 시각·길이는 첫 회차와 같다(기기 로컬 시간 기준). 매월 31일·매년 2월 29일처럼 없는 날짜인 달·해는 **건너뛴다**.
- `exdates`: 빠진 회차의 시작 날짜 목록. `COUNT`는 빠진 회차도 센다.
- **따로 고친 회차**: 반복 없는 별도 행으로 저장하고 `series_id`(원래 시리즈)와 `original_date`(원래 회차 날짜)를 둔다. 시리즈의 `exdates`에 그 날짜를 넣어 원래 회차는 숨긴다. 시리즈를 지우면 함께 지워진다.
- 범위별 수정·삭제 (`lib/series.ts`):
  - **이 일정만**: 시리즈 `exdates`에 날짜 추가 + 따로 고친 회차를 새로 만든다(삭제면 날짜만 추가).
  - **이후 모든 일정**: 시리즈를 그 회차 전까지로 자른다(`UNTIL`=전날, `COUNT`면 앞 회차 수). 고친 내용으로 그 회차부터 새 시리즈를 만든다(남은 `COUNT`·요일 이동 반영). 이후 날짜의 따로 고친 회차는 지운다. 첫 회차에서 고르면 "전체"와 같다.
  - **전체 일정**: 시리즈 시작을 옮긴 날짜 차이만큼 옮기고 시각·길이는 새 값으로. 매주 요일, `exdates`, 따로 고친 회차의 `original_date`도 같은 날짜 차이만큼 옮긴다. 반복을 "반복 안 함"으로 바꾸면 한 개짜리 일정이 된다.

- 시간은 `timestamptz`로 저장하고, 화면에서는 기기의 로컬 시간대로 보여준다.
- `end_at`은 **끝 미포함** 규칙이다. 종일 일정은 마지막 날 다음 날 자정이 `end_at`이다. 편집 창에서는 하루를 빼서 "마지막 날"로 보여준다.
- 태그는 개인용이라 별도 연결 테이블 없이 `events.tag_ids`·`tasks.tag_ids` 배열로 저장한다. 그래서 태그를 지울 때 앱이 직접 각 일정·할 일에서 그 id를 빼고 저장한다(DB가 자동으로 정리하지 않음).
- id는 앱에서 `crypto.randomUUID()`로 만들어 넣는다(`newId()`). 낙관적 업데이트에서 저장 전에 id가 필요하기 때문이다.
- 보안: 모든 테이블에 RLS(본인 `user_id` 행만 접근). 로그인한 사용자(`authenticated`)에게만 테이블 권한을 주고 `anon`은 막는다. `user_id`는 기본값 `auth.uid()`로 자동 기록된다.
- 실시간: 네 테이블 모두 `supabase_realtime`에 등록되어 있다. 변경이 오면 300ms 모아서 전체를 다시 불러온다.
- 저장은 낙관적 업데이트(화면 먼저 반영 → 저장)로 하고, 실패하면 상단 배너로 알린 뒤 서버 상태로 되돌린다.

## 5. 화면 구성

### 5.1 전체 레이아웃

- **데스크톱 / 아이패드 가로**: 왼쪽 사이드바 (캘린더 · 할 일 · 로드맵 · 카테고리 목록 · 태그 목록 · 설정) + 메인 영역
  - 사이드바의 카테고리/태그를 누르면 필터가 켜지고 꺼진다. 필터가 걸리면 선택 안 된 항목은 흐려지고, 위에 "필터 적용 중 / 해제" 버튼이 나온다.
  - 로컬 모드일 때 사이드바 아래에 "로컬 모드" 안내 표시
- **모바일** (폭 768px 미만): 상단 헤더 (기간 이동, 일/주/월 전환, 필터) + 하단 탭바 (캘린더 · 할 일 · 로드맵 · 설정)
  - 필터는 헤더의 필터 아이콘(걸린 개수 배지) → 하단 시트에서 카테고리·태그 칩을 고른다.
- 공통: 우측 하단 `+` 빠른 추가 버튼 → 보고 있는 날짜의 **다음 정각부터 1시간** 초안

### 5.2 캘린더 탭

- 보기 전환: **일간 / 주간 / 월간** (기본: **월간**, 모바일 포함. 기억하지 않고 열 때마다 월간). 보기를 바꿔도 보던 날짜를 유지한다.
- 한 주의 시작: **일요일**
- 모바일 주간 보기는 **3일 보기**를 기본으로 함 (버튼 이름도 "3일")
- 시간 표기: **24시간제** (시간축 `08:00`, 일정 `14:30~15:30`)
- 시간축: 30분 칸(높이 24px, 1시간 48px, `slotMinHeight`), 드래그는 15분 단위로 맞춤, 처음 열면 **지금 시각 2시간 전** 위치로 스크롤(새벽 2시 전이면 00:00). 시각 글자는 11px 흐린 글자 (2026-11-09)
- 시간축 칸(시각과 "종일" 글자) 너비 약 72px: FullCalendar가 글자 폭으로 칸 너비를 정하므로 `slotHeaderInnerClass`·`allDayHeaderInnerClass`로 글자에 좌우 여백(왼쪽 16px, 오른쪽 10px)을 줘서 넓힌다.
- 현재 시각 빨간 선 표시
- **일요일 날짜 숫자는 빨간색, 토요일은 파란색**(`--c-blue`) (월간 칸 숫자, 일·주간 머리글, 할 일 탭 미니 캘린더). 오늘·고른 날 표시가 우선
- **오늘**: 칸을 칠하지 않고 날짜 숫자에 **빨간 동그라미 + 흰 숫자** (월간 칸, 일·주간 머리) (2026-11-09)
- 일·주간 머리: 위에 요일(11px 흐린 글자, 주말 색), 아래 큰 날짜 숫자(17px). `dayHeaderContent`로 그린다. 월간 머리는 요일만.
- 일정 블록 내용: 시간 · 제목 (좁으면 제목이 다음 줄로), 태그는 **제목 아래 줄**(제목과 4px 띄움)에 `● 이름`으로 여러 개 나란히 표시. 상자 없이 점(7px)만 태그 색, 이름은 흐린 글자 11.5px, 태그 사이 8px. 일정 안의 작은 일정처럼 보이지 않게 하려는 모양이다.
- 반복 일정 회차는 제목 앞에 작은 **↻** 표시. 모바일 월간 보기에서는 칸이 좁아 숨긴다.
- 반복 회차를 드래그·리사이즈하면 놓은 뒤 **이 일정만 / 이후 모든 일정 / 전체 일정** 선택 창이 뜨고, 취소하면 제자리로 돌아간다.

**일간 / 주간 (시간축 타임라인)**
```
        일        월        화
      ┌────────┬────────┬────────┐
종일   │■ 출장 ──────────────▶   │   ← 종일·여러 날 일정
      ├────────┼────────┼────────┤
09:00 │■ 회의   │        │        │   ← 시간 일정 (카테고리 색 테두리 블록)
      └────────┴────────┴────────┘
```
- 캘린더에는 **일정만** 나온다. 할 일은 할 일 탭에서 따로 관리한다(2026-11-09 분리).

**월간**
- **모바일 월간 (폭 768px 미만, 2026-11-09)**: 위 **달력**(남은 높이의 64%) + 아래 **고른 날 일정 목록**.
  - 날짜를 누르면 그날을 **고른다**(숫자에 반전 동그라미, 오늘이면 빨간 동그라미 그대로). 빈 칸을 눌러도 새 일정 창이 열리지 않는다. "+N개"도 팝업 대신 그날을 고른다.
  - 처음엔 오늘. 달을 넘기면 그 달에 오늘이 있으면 오늘, 없으면 1일을 고른다. 고른 날은 저장하지 않는다.
  - 칸 안 일정은 **제목 한 줄짜리 작은 테두리 상자**(10px, 시간·태그·↻ 없음). 날짜 숫자는 20px로 조금 작게 해서 칸에 일정 1개 + "+N"이 들어가게 한다.
  - 달력은 **칸 줄 없이** 숫자를 칸 **가운데**에 보통 굵기(13px)로, 요일 머리는 11px 흐린 글자. 다른 달 칸은 칠하지 않고 숫자만 30%로 흐리게. 넘치면 상자 없는 흐린 "+N"(10px). 오늘·고른 날 숫자만 굵게.
  - 목록: 머리 "11월 11일 (수)"(오늘·내일·어제면 "… · 오늘"), 일정마다 테두리 상자에 [시간("종일" 또는 "10:00 ~ 11:00", 그날 밖으로 이어지면 "··") | 카테고리 색 세로줄 | 제목 ↻ / 태그 `● 이름`]. 종일 먼저, 그다음 시작 순. 누르면 편집 창. 없으면 "일정이 없어요."
  - 목록 맨 아래 **[+ 새 일정]**(고른 날 다음 정각 1시간). 모바일 월간에서는 오른쪽 아래 둥근 + 버튼을 숨긴다(일정을 가렸음).
  - 목록은 캘린더에 넘기는 일정(필터 적용, 반복 회차 펼침)을 그대로 쓴다.
- **데스크톱 월간 (폭 1024px 이상, 2026-11-09)**: 오른쪽에 **고른 날 일정 목록**(320px, 모바일과 같은 목록·[+ 새 일정]).
  - **날짜 숫자를 누르면** 그날을 고른다(반전 동그라미, 마우스를 올리면 흐린 동그라미). 빈 칸 클릭·드래그는 지금처럼 새 일정 창. 숫자 누름은 달력 칸의 `onPointerDownCapture`로 먼저 기록해 두고 FullCalendar `select`에서 새 일정 대신 그날 고르기로 바꾼다.
  - 월간에서는 둥근 + 버튼을 숨긴다(목록의 [+ 새 일정]). 768~1023px(아이패드 세로 등)은 달력이 좁아지므로 목록을 숨기고 + 버튼을 보인다.
  - 고른 날은 일·주간으로 바꿔도 유지된다(같은 달 안이면). 일·주간에는 목록이 없다.
- **모바일 스와이프**: 모든 보기에서 달력을 좌우로 밀면(가로 60px 이상, 세로보다 1.5배 이상) 이전·다음 기간. 편집 창이 열려 있으면 무시.
- 날짜 숫자는 "9일" 대신 **"9"**, 칸 **왼쪽 위** (`dayCellTopContent`·`dayCellTopClass`). 다른 달 날짜 칸은 숫자를 흐리게(40%) + 칸을 살짝 어둡게 (2026-11-09)
- 일정: 카테고리 색 테두리 막대 (시간 일정도 점이 아닌 막대, `eventDisplay="block"`), 칸이 넘치면 "+N개 더"
- 막대 두께는 그날 일정 수에 따라 바뀐다: 1개 가장 두껍게(위아래 여백 6px, 글자 13px) → 2개 4px → 3개 2px → 4개 이상 기본(1px). 여러 날 일정은 걸친 날 중 가장 많은 날 기준.

**드래그 (1단계부터 필수, 마우스와 터치 모두 지원)**
- 일정 블록 드래그 → 시간/날짜 이동 (종일 칸 ↔ 시간 칸 이동도 가능)
- 일정 블록 끝 드래그 → 기간 조절
- 빈 시간대 드래그 → 해당 범위로 새 일정 추가 창 열기
- 빈 시간대 **한 번 클릭** → 그 시각부터 **1시간짜리** 새 일정
- 일정 클릭 → 수정 창
- 터치: 0.25초 길게 누른 뒤 끌기
- 편집 창이 열려 있는 동안에는 캘린더 드래그·선택을 꺼서 클릭이 캘린더로 새지 않게 한다.
- 빈 칸 클릭·드래그는 **새 일정** 창으로 열린다.

**표시 옵션**
- 카테고리/태그 필터가 일정에 적용된다.

### 5.3 일정 / 할 일 추가·수정 창

```
┌─────────────────────────────────┐
│  새 일정 / 일정 수정        ✕    │
├─────────────────────────────────┤
│  제목                            │
│  🕐 날짜·시간   ☐ 종일  ↻ 반복    │
│  ■  카테고리                      │
│  #  태그 (여러 개)                │
│  🔔 알림 (여러 개)                │
│  ◎  로드맵 연결 (마일스톤)         │
│  ≡  메모                         │
├─────────────────────────────────┤
│                [삭제]  [ 저장 ]  │
└─────────────────────────────────┘
```
- 할 일 수정(할 일 탭에서 제목을 눌렀을 때): 시간 대신 "날짜"(하는 날, ✕로 지우면 날짜 없음 / "+ 날짜 정하기"), 반복 항목 없음, 제목 옆 완료 체크
- 데스크톱은 가운데 팝업, 모바일은 하단 시트
- 1단계 구현 범위: 제목, 시작/종료(날짜·시간), 종일, 카테고리(칩 1개 선택, 기본값은 첫 카테고리), 태그(칩 여러 개), 메모, 삭제
  - 반복·알림·로드맵 연결은 해당 단계에서 추가
  - 시작을 바꾸면 길이를 유지한 채 종료도 함께 이동한다.
  - 종료가 시작보다 앞서면 저장 시 1시간짜리로 보정한다.
  - 제목이 비면 "(제목 없음)"으로 저장한다.
  - Esc 또는 바깥 클릭으로 닫는다.
  - 날짜·시각 칸은 앱 모양 선택기(`components/pickers.tsx`, 2026-11-10). 브라우저 기본 `<input type="date|time">`은 쓰지 않는다(OS 언어에 따라 오전/오후로 보이고 모양이 앱과 다름).
    - 날짜: 버튼 "11월 10일 (화)"(올해가 아니면 연도도). 누르면 작은 달력(일요일 시작, ‹ › 달 이동, 오늘은 테두리, 고른 날은 칠함, [오늘]). 날을 고르면 닫힌다. 종료 날짜·반복 종료일은 시작보다 앞선 날을 누를 수 없다.
    - 시각: 버튼 "14:30"(24시간). 누르면 시(00–23)·분(5분 단위) 목록, 열 때 지금 값이 가운데. 분을 고르면 닫힌다. 5분 단위가 아닌 기존 값은 목록에 끼워 넣는다.
    - 펼침 창은 body에 띄워(fixed) 짧은 창(목표 수정 등)에서도 잘리지 않는다. 아래 자리가 없으면 위로, 오른쪽이 넘치면 왼쪽으로 민다. 바깥 누르기·바깥 스크롤·Esc로 닫히고, Esc는 편집 창까지 닫지 않는다.
    - 같은 선택기를 로드맵(목표 시작일·목표일, 마일스톤 할 일 바로 추가의 하는 날)과 설정(종일 일정·할 일 알림 시각)에도 쓴다.
- 일정·할 일이 같은 편집 창 `editor/item-editor.tsx`를 쓴다. [일정 | 할 일] 탭은 없앴다(2026-11-09): 캘린더에서는 일정만 만들고, 새 할 일은 할 일 탭 목록에서 바로 추가한다. 편집 창은 기존 할 일 수정에만 쓴다.
- 3a 반복 (일정 모드만):
  - "반복" 선택: 반복 안 함 / 매일 / 매주 ○요일 / 매월 ○일 / 매년 ○월 ○일 / 사용자 지정… (○는 시작 날짜 기준)
  - 사용자 지정: 간격 N + 단위(일·주·개월·년), 매주면 요일 토글(최소 1개), 종료(없음 / 날짜까지 / N회). 아래에 "2주마다 월·수요일, 5회" 같은 요약을 보여 준다.
  - 반복 회차를 누르면 그 회차의 날짜·시각으로 창이 열린다. 저장·삭제할 때 범위 선택 창(이 일정만 / 이후 모든 일정 / 전체 일정 / 취소)이 뜬다. 반복 규칙을 바꿨으면 "이 일정만"은 고를 수 없다.
  - 따로 고친 회차는 반복 칸 대신 "반복 일정에서 이 회차만 따로 고친 일정이에요."를 보여 준다.
  - 범위 선택 창에서 Esc는 선택 창만 닫는다(편집 창은 그대로).
- 3c 알림 (일정 모드만, 005 실행 후에만 보임): "알림" 줄에 칩 [없음] + 여러 개 선택
  - 시간 일정: 정시 / 5분 / 10분 / 30분 / 1시간 / 1일 전. 새 일정 기본값은 설정의 "새 일정" 값(처음 10분 전)
  - 종일 일정: 당일 09:00 / 전날 09:00 (시각은 설정의 종일 일정 알림 시각). 새 종일 일정 기본값은 당일
    - [+ 직접 정하기] (2026-11-10): 알림 줄 아래에 테두리 패널이 열린다. 맨 위 [당일|전날|2일 전|3일 전|7일 전] 붙은 버튼, 아래 [09] : [00] 시각 버튼과 [취소] [추가]. 시각 버튼을 누르면 24시간 시(00–23)·분(5분 단위) 목록이 열리고, 분을 고르면 닫힌다. 브라우저 기본 선택 상자·시각 입력은 투박하고 오전/오후로 보여서 쓰지 않는다. 더한 시점은 칩 "전날 21:30 ✕"로 보이고 ✕로 뺀다. 여러 개 가능, 먼저 울리는 것부터 정렬. 기본 선택지와 같은 시점(예: 전날 09:00)을 더하면 그 선택지가 켜진다
    - 직접 정한 시각은 설정의 종일 알림 시각을 바꿔도 그대로다(기본 선택지만 따라 바뀐다)
  - 종일 ↔ 시간 일정으로 바꾸면 선택지가 달라서 그 종류의 기본값으로 바뀐다
  - 반복 일정의 알림은 모든 회차에 같이 적용된다(따로 고친 회차는 자기 값)
  - 005 이전에 만든 일정은 알림이 없다(기본값을 일괄 적용하지 않음)
- 4a 로드맵 (일정·할 일 모두, 마일스톤이 하나라도 있을 때만 보임): 메모 위 "로드맵" 줄에 선택 상자. 목표별 묶음(optgroup) 아래 마일스톤, 맨 위 "연결 안 함". 보관한 목표는 빠지지만 지금 연결된 목표는 보관돼도 남는다.

### 5.4 할 일 탭 (2026-11-09 개편)

```
┌ 할 일 ──────────────────────────────────────────── [필터] ┐
│ 2026년 11월   ‹ 오늘 ›   │ 11월 9일 (월) 오늘        1 / 3 완료 │
│ 일 월 화 수 목 금 토      │ ┌ 밀린 할 일 2 ─────────────────┐ │
│ ◌  ◌  ◔  ◑  ✔  ◌  ◌      │ │☐ 어제 못 한 일  어제  [오늘로] ⋯│ │
│ 1  2  3  4  5  6  7      │ └──────────────────────────────┘ │
│ ...                      │ (업무 ＋)                         │
│                          │ ☑ 보고서 초안                  ⋯ │
│                          │ ☐ 메일 정리   ● 중요           ⋯ │
│                          │ (운동 ＋)                         │
│                          │ ☐ 스쿼트 50개                  ⋯ │
└──────────────────────────┴──────────────────────────────────┘
```
- 데스크톱: 왼쪽 **월간 미니 캘린더**, 오른쪽 **고른 날의 할 일**. 모바일: 미니 캘린더가 위, 목록이 아래(함께 스크롤).
- 데스크톱의 두 칸 사이 경계선을 **끌어서 너비 조절**(기본 360px, 최소 320px(링 7개가 들어가는 폭), 목록은 최소 320px 남김). 마우스를 올리면 가운데 손잡이가 보이고, 두 번 누르면 기본 너비, 키보드 ←/→로 16px씩. 너비는 기기에 저장(`daypath:todos-split`).
- 목록은 경계선 쪽에 붙여 그린다(최대 너비 2xl). 경계선을 옮기면 목록도 따라 움직인다.
- 처음 열면 오늘이 선택된다. 고른 날짜는 저장하지 않는다.
- **미니 캘린더** (일요일 시작, 다른 달 날짜 칸은 비움):
  - 날짜 숫자 위에 **진행률 링**: 할 일이 없으면 흐린 점선 원, 있으면 끝낸 비율만큼 진한 호 + 가운데 **남은 할 일 수**(13px), 모두 끝내면 원 + 체크. 링 지름 36px, 날짜 숫자 14px, 줄 간격 8px. 색은 칠하지 않고 글자색만 쓴다.
  - 고른 날은 숫자가 반전된 동그라미, 오늘은 빨간 굵은 숫자, 일요일은 빨간 숫자, 토요일은 파란 숫자. ‹ › 로 달 이동, "오늘"은 오늘 날짜로.
  - 링은 필터가 적용된 할 일로 계산한다.
- **목록**:
  - 머리: "11월 9일 (월)", 오늘이면 빨간 "오늘", 오른쪽에 "완료 N / 전체 M".
  - **카테고리별 묶음**: 설정의 카테고리 순서대로, 비어 있어도 모두 보인다. 머리글은 카테고리 색 테두리 알약 + `＋`. "카테고리 없음" 묶음은 그날 그런 할 일이 있을 때만 맨 뒤. 카테고리가 하나도 없으면 "할 일" 묶음 하나.
  - 카테고리 필터가 걸려 있으면 그 카테고리 묶음만 보인다.
  - 묶음 안은 만든 순서. 완료한 할 일도 제자리에 남고 흐린 취소선.
  - `＋`를 누르면 묶음 끝에 입력칸이 생긴다. Enter로 추가하고 칸은 열린 채 이어서 입력, Esc나 빈 칸에서 포커스가 빠지면 닫힌다. 새 할 일의 날짜는 고른 날, 카테고리는 그 묶음. 태그 필터를 하나만 걸어 두었으면 그 태그도 붙인다.
  - **밀린 할 일**: 오늘을 볼 때만, 오늘 이전 날짜인데 못 끝낸 할 일을 맨 위 테두리 상자에 모은다(오래된 날짜 먼저, 원래 날짜를 빨간 글자로). [오늘로]로 날짜를 오늘로 옮긴다. 미니 캘린더에서는 원래 날짜에 그대로 남는다.
  - **날짜 없음**: 오늘을 볼 때만 맨 아래에 접을 수 있는 묶음으로(예전에 마감일 없이 만든 할 일).
- **행**: 카테고리 색 체크박스(20px) · 제목 · 아래 줄에 (마일스톤에 연결돼 있으면) `◎ 마일스톤 이름`, 태그 `● 이름` · 오른쪽 `⋯` 메뉴. 체크박스는 완료만 바꾸고, 제목을 누르면 편집 창. 마일스톤 이름은 할 일 행에만 보이고 캘린더 일정에는 보이지 않는다.
- `⋯` 메뉴: 수정 / 오늘 하기(오늘이 아닐 때) / 내일 하기(미래 날짜면 "다음 날로") / 삭제(확인 없이 바로).
- 필터: 카테고리, 태그 (사이드바·모바일 시트와 같은 필터)

### 5.5 로드맵 탭 (4a, 2026-11-09)

```
┌ 로드맵 ─────────────────────────────────────────── [+ 목표] ┐
│ ┃토익 900점    25% │ ┃토익 900점                 12/31 · D-52 │
│ ┃▬▬▱▱▱▱  D-52     │ ┃▬▬▬▱▱▱▱▱▱▱▱▱             25%           │
│ ┃운동 습관      0% │   마일스톤 1 / 4 완료   (메모)            │
│                   │ ✔ 단어 2000개          11/30   100%      │
│ ▸ 보관함 1        │   ▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬ 2/2                    │
│                   │   ☑ Day 1-10 단어   11월 7일 (토)     ⋯  │
│                   │   + 할 일                                │
│                   │ ○ 모의고사 3회         12/20     0%      │
│                   │   ☐ 1회 풀기  어제                  ⋯  │
│                   │   ▦ 모의고사 시험  11/12 18:48           │
│                   │ + 마일스톤                               │
└───────────────────┴──────────────────────────────────────────┘
```
- 데스크톱: 왼쪽 **목표 목록**(288px), 오른쪽 **고른 목표 상세**. 모바일: 목록 → 목표를 누르면 상세, 머리의 ‹ 로 목록으로.
- 목표가 없으면 "첫 목표 만들기" 안내.
- **목표 목록**: 왼쪽 3px 목표 색 테두리 + 제목 + 진행률 % + 얇은 막대 + D-day(목표일이 있을 때). 보관한 목표는 아래 접힌 "보관함 N"에서 열어 볼 수 있다.
- 정렬: 목표는 목표일 순(없으면 뒤) → 정렬 순서 → 만든 순. 마일스톤도 같은 규칙. 마일스톤 안 할 일은 안 끝낸 것 먼저, 그다음 날짜 순.
- **목표 상세**: 머리(목표 색 왼쪽 테두리, 제목을 누르면 목표 수정 창, 목표일 · D-day, 진행률 막대, "마일스톤 N / M 완료", 메모) → 마일스톤 묶음들 → "+ 마일스톤"(바로 입력).
- **마일스톤 묶음**: 
  - 왼쪽 상태 원: 할 일이 없으면 눌러서 직접 완료 체크, 할 일이 있으면 진행률로 자동(누를 수 없음). 완료면 목표 색 테두리 원 + 체크(칠하지 않음).
  - 제목(누르면 마일스톤 수정 창), 목표일(지났고 안 끝났으면 빨간 글자), 진행률 %, 할 일이 있으면 막대 + "끝낸 수/전체".
  - 접기 (2026-11-10): 줄 오른쪽 끝 ⌄ 버튼으로 마일스톤마다 접고 편다(접으면 ›). 접으면 머리 줄과 진행 막대만 남고 할 일·일정·"+ 할 일"은 숨긴다. 마일스톤이 2개 이상이면 목록 위 오른쪽에 [모두 접기] / [모두 펼치기](모두 접혀 있을 때) 버튼. 접은 상태는 기기에 저장(`daypath:roadmap-folded`, 10.5)하고 처음엔 모두 펼쳐져 있다.
  - 연결된 할 일은 할 일 탭과 같은 행(체크·⋯ 메뉴·제목 누르면 편집 창). 날짜는 흐린 글자(지났으면 빨간 글자), 마일스톤 이름은 빼고 보여 준다.
  - 연결된 일정은 달력 아이콘 + 제목 + 날짜·시각("· 반복"). 누르면 일정 편집 창.
  - "+ 할 일": 제목 + 날짜(선택) 입력. Enter로 추가하고 칸은 열린 채 이어서 입력, Esc나 빈 칸에서 포커스가 빠지면 닫힌다. 카테고리·태그 없이 그 마일스톤에 연결된다.
- **D-day**: 목표일까지 "D-52", 당일 "D-day", 지나면 "D+3". 날짜는 "11/30" 짧은 형식.
- **목표 수정 창** (데스크톱 가운데 팝업, 모바일 아래 시트): 제목, 색(10색 테두리 원), 시작일(선택, "+ 시작일 정하기"는 오늘로 시작, 4b), 목표일(선택, "+ 목표일 정하기"는 한 달 뒤로 시작), 메모. 시작일이 목표일보다 늦으면 저장할 때 둘을 바꾼다. 아래: 삭제(안내 "목표와 마일스톤을 지워요. 연결된 할 일·일정은 남아요." + [취소][삭제]) · 보관/보관 해제 · 저장.
- **마일스톤 수정 창**: 제목, 목표일, 삭제(연결된 할 일·일정은 남음), 저장.
- 연결은 두 곳에서: 로드맵의 "+ 할 일", 그리고 일정·할 일 편집 창의 "로드맵" 선택 (5.3).

```
로드맵  [목록|타임라인]                                  [+ 목표]

              │ 10월      11월  (오늘)  12월      2027년 1월
토익 900점    │ ┌────────◆──────┃──────◆─◆─┐
50% · 12/31   │ └▬▬▬▬▬▬▬▬▬▬     ┃          ┘  단어 2000개 …
운동 습관      │      ┌┄┄┄┄┄┄┄┄┄┄┃┄┄┄◇
0%            │                ┃     주 3회 4주
```
- 로드맵 머리의 [목록 | 타임라인]으로 바꾼다(목표가 있을 때만 보임, 저장하지 않음 → 처음엔 목록). 타임라인에는 **보관하지 않은 목표만** 한 화면에 줄마다 하나씩(목록과 같은 순서).
- 왼쪽 이름 칸(데스크톱 192px, 모바일 120px)은 가로 스크롤해도 고정: 목표 색 왼쪽 테두리 + 제목 + 진행률 · 목표일. 누르면 목록 보기의 그 목표 상세로 간다.
- **막대**: 시작일(없으면 목표를 만든 날) → 목표일, 목표 색 테두리(칠하지 않음). 막대 안 아래쪽 얇은 선이 진행률. 목표일이 없으면 오른쪽이 열린 **점선 막대**(마지막 마일스톤 날짜나 오늘 중 늦은 날까지). 누르면 목표 수정 창.
- **마일스톤 ◆**: 날짜가 있는 마일스톤만 그 날짜에. 안 끝남은 테두리만, 끝남은 목표 색으로 채움, 날짜가 지났는데 안 끝났으면 빨간 테두리·이름. 아래에 이름을 쓰되 앞 이름과 겹치면 생략(마우스를 올리면 보임). 누르면 마일스톤 수정 창.
- **단위**: 월(하루 6px) / 분기(2px) / 년(0.6px). 머리에 달 이름(년 단위는 1·4·7·10월만), 1월과 맨 앞에는 연도. 달 경계 세로선, 오늘은 빨간 세로선 + "오늘" 표시.
- 기간: 모든 막대·마일스톤·오늘을 포함해 앞 1달·뒤 2달 여유, 최소 7 / 13 / 37개월. 처음 열 때와 단위를 바꿀 때 오늘이 왼쪽 1/4쯤 오게 스크롤하고, [오늘]로 다시 맞춘다.
- **보기 전용**: 끌어서 날짜를 바꾸지 않는다. 날짜는 수정 창에서 바꾼다.

### 동작 방식 (3c, 2026-11-09)

1. 앱(브라우저): 일정·할 일·설정이 바뀌거나 앱을 열면 `lib/reminders.ts`의 `buildQueue`가 반복 회차까지 펼쳐 앞으로 30일치 알림을 계산하고, RPC `replace_push_queue`로 Supabase `push_queue`에 통째로 넘긴다.
2. Supabase: pg_cron이 1분마다 `send_due_pushes()`를 실행한다. 보낼 때가 된 예약과 그 계정의 기기 구독을 묶어 pg_net으로 Vercel `/api/push`에 POST한다.
3. Vercel `/api/push`: VAPID 키로 서명해 각 기기로 Web Push를 보낸다. 404/410(구독이 끝난 기기)은 RPC `remove_push_subscriptions`로 지운다.
4. 기기: `public/sw.js`가 알림을 띄우고, 누르면 앱을 연다.

- **예약 범위 30일**(사용자 선택): 반복 일정 계산이 앱 코드에만 있어서, 앱이 앞으로 30일치를 계산해 서버에 넘긴다. 어느 기기든 앱을 열면(그리고 열어 둔 동안 1시간마다) 다시 계산한다. **30일 넘게 앱을 열지 않으면 그 뒤 알림은 멈춘다.**
- 동기화: 데이터가 처음 제대로 불러와진 뒤(`ready`)에만, 바뀐 뒤 2초 기다렸다가, 계산 결과가 지난번과 같으면 보내지 않는다(`lib/data/notify.tsx`). 불러오기 실패로 빈 데이터일 때 예약을 지우지 않게 하려는 것.
- 예약 시각은 기기 로컬 시간으로 계산한 절대 시각(UTC 저장). 15분 넘게 늦어진 예약은 보내지 않는다.
- Vercel `/api/push`는 DB를 읽지 않고, DB가 보낸 알림 하나 + 기기 구독 목록만 받아 서명해 보낸다. `x-push-secret` 헤더가 `PUSH_SECRET`과 같아야 한다. **service_role 키는 어디에도 쓰지 않는다.**
- 비밀 값: Vercel 환경 변수 `NEXT_PUBLIC_VAPID_PUBLIC_KEY`·`VAPID_PRIVATE_KEY`·`PUSH_SECRET`(선택 `VAPID_SUBJECT`, 기본은 앱 주소). Supabase Vault `daypath_push_secret`(= PUSH_SECRET)·`daypath_app_url`. 키는 `node scripts/make-push-keys.mjs`로 만든다. git에 올리지 않는다.
  - Vercel 화면(2026-11): 환경 변수는 **Settings → Environments → Production → Environment Variables**에 있다. 종류는 `NEXT_PUBLIC_VAPID_PUBLIC_KEY`만 **Config**(공개 값이라 Secret이면 경고가 뜨고 저장이 막힌다), `VAPID_PRIVATE_KEY`·`PUSH_SECRET`은 **Secret**. 비공개 값에는 `NEXT_PUBLIC_`을 붙이지 않는다(브라우저 코드에 들어감).
  - `NEXT_PUBLIC_` 값은 빌드할 때 코드에 들어가므로, 바꾸면 다시 배포해야 반영된다.
- 알림은 클라우드 모드 전용(로컬 모드는 서버가 없음).

## 10. 다른 PC에서 이어서 작업하기

### 10.1 처음 세팅

1. Git과 Node.js(20.9 이상, 권장 24 = `.nvmrc`)를 설치한다. Windows PC는 v24.11.1.
   - macOS: `brew install git node@24` (또는 nvm이면 저장소에서 `nvm use`)
   - Windows: git-scm.com, nodejs.org 설치 파일
2. `git clone https://github.com/ieuns7320/Daypath.git` 후 `npm install`
   - `package-lock.json`에 Windows·macOS(Apple Silicon·Intel)용 네이티브 패키지(sharp, Next SWC, Tailwind, lightningcss)가 모두 들어 있어 어느 쪽에서든 `npm install`만 하면 된다. lock 파일을 지우고 새로 만들지 않는다.
3. `.env.example`을 복사해 `.env.local`을 만들고 두 값을 넣는다(`cp .env.example .env.local`). 값은 Supabase 대시보드 → Project Settings → API에서 확인한다. 다른 PC의 `.env.local`을 메신저·메일로 옮기지 않는다.
   - `NEXT_PUBLIC_SUPABASE_URL` = `https://xcbmvnhjowsuycfbapvn.supabase.co`
   - `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` = 대시보드의 **Publishable key** (`sb_publishable_...`). Secret / service_role 키는 절대 넣지 않는다.
4. `npm run dev` → http://localhost:3000 에서 기존 계정(이메일+비밀번호)으로 로그인한다. 새 계정을 만들 필요 없다.
5. 타입 검사 전에 한 번 `npx next typegen`을 실행한다(`LayoutProps` 같은 라우트 타입 생성).
6. 작업을 시작할 때는 `git pull`, 끝낼 때는 커밋 후 `git push`를 한다. **PC를 옮기기 전에 push하지 않으면 다른 PC에서 그 작업이 안 보인다.**
7. Claude Code는 저장소 폴더에서 연다. `CLAUDE.md` → 이 문서 순서로 읽으므로 대화가 이어지지 않아도 맥락을 잡는다. Claude 메모리는 PC마다 따로라서 공통 규칙은 `CLAUDE.md`·이 문서에만 둔다.

**PC 간 공통 설정 (2026-11-09)**
- 줄 끝: `.gitattributes`로 **LF 통일**(`* text=auto eol=lf`). Windows의 `core.autocrlf=true`여도 저장소에는 LF로 들어간다. 커밋 때 "LF will be replaced by CRLF" 경고는 무시해도 된다.
- Node 버전: `.nvmrc` = 24.
- `.claude/launch.json`의 두 서버(3000 클라우드, 3001 로컬 모드)는 macOS에서도 그대로 쓴다(`npx`를 셸로 실행).
- 로컬 모드 데이터(`daypath:v1`)와 할 일 칸 너비 같은 브라우저 저장값은 기기·브라우저마다 따로다(10.5). 클라우드 데이터는 같다.

DB는 클라우드(Supabase)에 있으므로 PC를 옮겨도 SQL을 다시 실행할 필요가 없다. 새 마이그레이션 파일이 생겼을 때만 그 파일을 실행한다.

### 10.3 개발 서버와 확인 방법

- `.claude/launch.json`에 서버 두 개가 있다.
  - `daypath-dev`: `npm run dev`, 포트 3000, `.env.local`을 읽어 **클라우드 모드**

- Next 16은 같은 폴더에서 `next dev`를 **하나만** 띄울 수 있다("Another next dev server is already running"). 두 모드를 바꿀 때는 하나를 끄고 다른 하나를 켠다.
- 작업 후 확인 순서: 브라우저로 화면 확인(데스크톱·모바일 375px·라이트/다크) → `npx tsc --noEmit` → `npx eslint src` → `npx next build`.
- 개발 중 콘솔의 `Route "/calendar": Could not validate that a segment in your UI has instant navigation` 에러는 Next 16 개발 모드의 검사 메시지다. 모든 탭에서 나오고 동작에는 영향이 없어 지금은 무시한다. 원인은 아직 확인하지 않았다(브라우저 전용 렌더링 `dynamic(..., { ssr: false })` 때문으로 추정). 없애려면 각 페이지에 `export const instant = false`를 두는 방법이 메시지에 안내되어 있다.
- `next dev`가 `AGENTS.md`를 다시 써 넣을 수 있다. 내용이 같으면 그대로 커밋해도 된다.
- Windows 메모: PowerShell에서 `git push`가 빨간 `NativeCommandError`를 보여도 git이 stderr에 진행 상황을 쓴 것뿐이라 성공일 수 있다(출력의 `main -> main` 확인). curl은 `--ssl-no-revoke`가 필요할 수 있다.
- macOS 메모: 셸은 zsh. 위 Windows 메모는 해당 없다. 3000·3001 포트가 남아 있으면 `lsof -ti :3000 | xargs kill`로 끈다. 아이콘 스크립트(`scripts/make-icons.mjs`)의 sharp도 macOS에서 그대로 돈다.

- 반복 일정: 캘린더는 보이는 기간(`datesSet`)만큼 회차를 펼쳐 FullCalendar id를 `event:<시리즈 id>@<날짜>`로 준다. 회차를 고치면 `series.ts`가 변경 목록을 만들고 `applyEventChanges`가 한 번에 저장한다.

- 실시간: 다른 기기·탭에서 바뀌면 `subscribe`가 알려 주고, 300ms 모아서 전체를 다시 불러온다(부분 갱신 없음, 개인용이라 충분).

### 10.6 알려진 문제·확인 못 한 것

- 날짜·시각 선택기(2026-11-10)는 로컬 모드에서 편집 창(모바일 다크·데스크톱 라이트)과 로드맵 목표 창으로 확인했다. 설정 화면의 알림 시각은 클라우드 모드에서만 보여 화면으로는 확인하지 못했다(같은 컴포넌트).
- 모바일 일간 보기 제목("2026년 11월 6일")은 헤더가 좁아 잘릴 수 있다. 확인하지 않았다.
- "Can't perform a React state update on a component that hasn't mounted yet" 에러는 마운트 후 렌더링으로 고쳤지만, 원래 재현이 잘 안 되던 문제라 다시 보이면 원인을 다시 본다 (2장 구현 시 주의).
- 4a 로드맵은 로컬 모드(3001)에서만 확인했다(진행률 계산, 바로 추가, 보관·해제, 편집 창 연결, 할 일 행 표시, 모바일 375px·라이트/다크). 2026-11-09 클라우드에 `006_roadmap.sql`을 실행했고 배포 주소에서 로드맵이 보이는 것을 사용자가 확인했다.
- 4b 타임라인은 로컬 모드(3001)에서 확인했다(월·분기·년, 열린 막대, 이름 겹침 생략, 막대·◆·이름 누르기, 시작일 저장·뒤바뀜 보정, 모바일 375px·라이트/다크).
- 로드맵에서 목표·마일스톤 순서를 끌어서 바꾸는 기능은 없다(목표일 순 자동 정렬).
- 3c 알림: 예약 계산(`buildQueue`)은 임시 스크립트로 확인했고(시간·종일·반복 회차·빠진 회차·할 일 묶음·지난 시각 제외), `/api/push`가 비밀 없는 요청을 403으로 막는 것까지 확인했다. 2026-11-09 사용자가 키·SQL을 설정했고, **iPhone(홈 화면 앱)과 Windows PC 모두 테스트 알림이 왔다**(pg_cron → Vercel → 기기 전체 경로 확인). 일정·할 일 예약 알림은 같은 경로를 쓰며, 실제 시각에 오는지는 쓰면서 확인한다.
- VAPID 키를 바꾸면 기존 기기 구독이 맞지 않아 알림이 안 간다. 그때는 각 기기에서 알림을 끄고 다시 켠다.
- 알림을 눌렀을 때 해당 날짜로 가지 않고 캘린더/할 일 탭만 연다.
- 반복 일정은 로컬 모드(3001)에서만 확인했다. 003·004는 2026-11-09 클라우드에 실행했다. 클라우드에서 반복 일정 저장·실시간 동기화는 사용자가 쓰면서 확인한다.
- 반복 회차는 기기 로컬 시간으로 펼친다. 시간대가 다른 기기에서 보거나 서머타임이 있는 지역에서는 시각이 어긋날 수 있다(지금은 한국만 써서 무시).
- 반복 규칙 계산 테스트는 저장소에 없다(작업 중 임시 스크립트로만 확인). 테스트 도구를 넣을 때 `recurrence.ts`·`series.ts`부터 옮긴다.
